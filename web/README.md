# web/ —— 运营台前端

Vite + React 18 + TypeScript / TanStack Table + Virtual / Tailwind + 自建 shadcn 风格组件 / Recharts。

```bash
npm install
npm run dev        # → http://127.0.0.1:5173,/v1 由 Vite 代到 8781
npm run build      # → dist/,由 server/app.py 挂在 / 上
npx tsc -b         # 只做类型检查
```

四页:**任务队列**(主界面)/ **买家号** / **工作流记录** / **错误码分布**。

## 写进代码的几条规矩

**封闭集不存副本。** 状态、物流状态、事件类型、错误码及其四个处置分组,
全部由 `GET /v1/admin/meta` 下发。这个项目已经因为「两份副本悄悄分叉」栽过两次
(厂商的 `subTotal`/`subtotal`、我们自己的 docs 目录树)。
想加一个状态,改 `services/vocab.py` 一处就够。

界面上出现一个陌生的英文枚举是**对的** —— 那说明服务端加了新值而前端还没发版。
静默映射成「未知」会让人以为库里真有个叫「未知」的状态。

**词汇表缺键就不渲染,并且说出缺了哪个。** 前后端分开发布,版本一错位就会对
`undefined` 调 `.includes`,整站白屏。白屏跟「服务挂了」「网断了」长得一模一样,
运营会去重启一台其实好好的机器。所以 `MetaGate` 校验形状,缺了就明说缺哪个键。

**「没说上话」和「服务说不行」是两句话。** `ApiResult` 分 `transport` / `business`,
调用方必须分别处理 —— 界面上「查不到」和「服务挂了」混成一句,
会让人跑去上游翻一张其实好好的单。

**复制失败要出声。** `navigator.clipboard` 只在安全上下文可用。静默失败在这里特别毒:
运营以为地址已经复制,粘到亚马逊的却是上一次的剪贴板内容,包裹直接寄错人。
所以 `CopyText` 失败会变红说「复制失败」,并且有 `execCommand` 兜底。

**红色要跟真正那道闸算的是同一件事。** 限价是**整单**的(`price_guard` 判的是
`actual_total > price_cap`),所以只有「实付总计」那一格会因超限变红,单价不着色。
拿单价去比会得出跟护栏相反的结论:3 件 × 24、限价 60,单价看着安全、整单其实已经超了。

**危险动作前端不替人做决定。** 重置一律先按 `acknowledged: false` 发,
让服务端那道 `NEEDS_ACK` 闸自己判;它拒了再弹确认条给人回应。
由前端看错误码自动带上 `acknowledged`,等于把闸拆了 ——
而闸上写着的正是「这一单可能已经真下成了」。

**必然被拒的按钮不该亮着。** 已下单/已取消的单点「改地址」服务端会以 `BAD_STATUS` 拒,
所以那两个按钮在这些状态下不渲染。一个点下去必然被拒的按钮,
是在让人以为自己做错了什么。

**只发真改动过的字段。** 地址表单原样回传六个字段的话,事件流里那条 `before`/`after`
会记成「六个字段全改了」,以后查「谁把州改错了」就查不出来了。

**别在界面上撒谎。** `RETRYABLE` 那一组目前**没有任何自动重试在消费它** ——
没有 workflow 把 `exception` 退回 `ready`。所以错误码分布页写的是
「目前没有自动重试,要人进去点」,不是「系统自己会再试」。
服务端把 `auto_retry_implemented` 这一位吐给前端就是为了这句话;
哪天真做了自动重试,`tests/test_error_codes.py` 会提醒来改文案。

**一张永远红着的卡片会把人训练成忽略红色。** 工作流记录页只把「该定时却太久没跑」
标红;`db_init` 这种装机时跑一次的按需工作流标灰。
期望写在 `services/ops_query.EXPECTED_INTERVAL`,加了工作流却没声明的测试会断。

**折线图上「平了」和「没数据」长得一样,含义正好相反。** 所以按天的趋势图会把
没出错的那天补成 0,并且用 `linear` 而不是 `monotone`——
后者会在两天之间画出从没存在过的峰值。

**批量动作不替人做那个必须由人做的确认。** 批量重置调的是一个**没有 `acknowledged`
参数**的接口。能重的都重,可能已下单的原样报回来,界面把它们单独列成一行紫字,
说清楚「点开逐条去买家号的订单页看过再重置」。「跳过」不是失败 ——
混进失败里会让人以为系统出了问题,于是重试,于是绕过那道闸。

勾选框只在拍单异常 / 待人工的行上可用:让必然被拒的单能被勾上,
只会换来一份「失败 18 条」的清单。换了筛选或翻了页就清空勾选 ——
留着的话,「重置选中的 12 条」会包含现在根本看不见的单。

**导出的是整个筛选结果,不是当前这一页。** 只导一页是最阴的那种错:
表看着完整、其实少了后面几千行,而且没有任何地方提示少了。

**「操作人」不是登录。** 自己填的名字,存浏览器本地,由 api 层统一带上。
这套东西不做鉴权(所有者定稿),没有可信身份可用 ——
它只是让人工动作在事件流里带上一个人名,拦不住任何人。界面上写明了这一点。

## 两种行密度

- **详细**(~124px):照厂商面板那一行做,8 组字段竖着堆在各自格子里
  (所有者定稿:「这是订单详情,需要把它作为模板」)。运营不用点开就能核对
  地址、费用、物流 —— 这正是他们现在的工作方式。
- **紧凑**(40px):一行一条,用来扫桶:今天异常几单、卡在哪。

表格用 `display: grid` 而不是默认的 table 布局 —— 虚拟滚动要给行绝对定位,
原生 table 的行排不动。

## 订单详情

**点行才弹**,不默认占着右边一栏(所有者定稿)。布局照厂商面板那一行的
8 组字段与顺序,分组名也沿用他们的说法 —— 运营从那边迁过来时,
眼睛不用重新学一遍东西放在哪。

与厂商那边有两处刻意的不同:

- 他们整段执行过程只有一个 `failContent` 自由文本字段;我们换成只追加的事件时间线。
- 危险动作(强制回填)必须先过一个**预览步**,把「要写进库的到底是什么」摊开说清楚。

## 点击即复制

ASIN、上游单号、AMZ 单号、收货各字段、运单号、买家号 ID,外加收货地址「复制整段」。
规则挂在 `CopyText` 上,不是一个字段一个字段挂事件。复制不冒泡 ——
行本身是可点的(点行开详情),复制不该顺手把弹窗也开了。
